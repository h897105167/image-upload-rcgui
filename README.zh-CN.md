# Image Upload RCGUI

**往 Obsidian 笔记里一粘图，图就落到你自己的 rclone 远程上** —— 插件把图片字节交给 RCGUI 的 `imagehost` 插件在本机开的 HTTP 服务，上传成功后把本地链接改写成一个托管 URL。

[English](README.md) | 简体中文

Obsidian 本来会把粘贴的图片存进库里并插入 `![[attachment.png]]`。这个插件让它照常发生，然后把那条刚写下的引用换成 `![|300x200](https://…)`：图片已经在远程上，尺寸按笔记里的显示需要收敛。除了传到你自己的远程，字节不经过任何第三方图床。

- 相关仓库：[RCGUI](https://github.com/h897105167/rclone_gui_windows) · [imagehost 插件](https://github.com/h897105167/rcgui-plugin-imagehost)
- 插件 id `image-upload-rcgui`，版本 1.2.0，要求 Obsidian 1.4.0 及以上。

## 环境要求

| 需要什么 | 从哪来 |
| --- | --- |
| 开着的 RCGUI 桌面程序 | <https://github.com/h897105167/rclone_gui_windows> |
| `imagehost` 插件，且它的 HTTP 服务已开启 | <https://github.com/h897105167/rcgui-plugin-imagehost>（RCGUI 自带） |

端口由 RCGUI 说了算：默认 `5273`，被占用时它会提示。跑 Obsidian 的那台机器要能连到这个服务——同一台机器用 `127.0.0.1`；Obsidian 在别的设备上，就把完整地址填进 `服务地址`。

## 安装

这个仓库就是分发形态：把 `manifest.json` 和 `main.js` 拷进 `<库>/.obsidian/plugins/image-upload-rcgui/`，然后在 Obsidian 的社区插件列表里启用 **Image Upload RCGUI**。

```text
.obsidian/plugins/image-upload-rcgui/
  manifest.json
  main.js
```

装好后打开插件设置按一次 **自动检测**：先探配置的端口，再退到 `5273`，最后把 `5270–5285` 扫一遍。服务开在非默认端口上通常也能直接认出来，不用手填。

## 设置项

改动要点 **保存** 才生效（设置页改的是草稿副本）；点 **恢复默认** 会把草稿丢掉。

| 设置项 | 默认值 | 作用 |
| --- | --- | --- |
| `RCGUI 端口` | `5273` | 宿主 HTTP 服务的端口，旁边带 **自动检测** 按钮。 |
| `服务地址（可留空）` | 空 | 填了就盖过端口，例如 `http://192.168.1.10:5273`。 |
| `最大宽度` | `300` | 笔记里的显示宽度；`0` 表示不限制。 |
| `最大高度` | `300` | 显示高度；和宽度一起构成一个框，按比例缩放。 |
| `上传前真的缩小图片` | 关 | 关闭时原图照传，只限制显示尺寸；打开后按上面两个值重编码文件本身。 |
| `粘贴时自动上传` | 开 | 关掉后粘贴的图片留在本地，只能从右键菜单或命令上传。 |
| `上传后删除本地文件` | 开 | 只对库里的图片文件生效，而且进回收站，可以找回。 |
| `插入哪种链接` | `直链` | `短链` 需要 RCGUI 那侧的短链模板可用；失败会自动退回直链。 |
| `内链换外链` | 开 | 连 `![[img.png]]` 也换成托管 URL，而不是留着维基链接。 |

## 日常怎么用

- **粘贴或拖入图片。** 上传自己就开始了；状态栏显示已经等了多少秒，到 60 / 180 / 360 秒会各提醒一次，慢也不会看着像卡死。
- **在文件列表里右键某个文件**：**上传图片** 会把它传上去并复制链接。当前笔记里指向这个文件的引用都会被改写，提示里会说改了几处。
- **在笔记里右键**：对着图片引用是 **上传图片**，对着一段含图片的选中内容是 **上传图片（选中内容里的图片）**。
- **命令面板**（命令名就是中文）：`上传剪贴板里的图片`、`检测 RCGUI 服务`、`上传当前笔记里选中的图片引用`。
- **状态栏**显示 `● RCGUI 图床：就绪`；检测中、上传中是 `◌`；服务不在是 `○`。

上传是**一条一条排队**的：插件把并发请求串起来，因为同时发三个请求时，其中一个对着本机服务跑了 28 秒。

## 笔记里最终长什么样

`![|300x200](https://…)` —— 那组数字只决定图片画多大，远程上的文件仍是原始像素。两个方向的数字来自同一个缩放系数，所以宽高比不会被拉变形；本来就放得下的图压根不带尺寸后缀。

- 作者自己写过的尺寸优先：`![[a.png|400]]` 会变成 `![|400](https://…)`，不会被强行改成配置里的框。
- 说明文字会留下：`![shot](a.png)` 变成 `![shot|300x200](https://…)`。
- 空目录、带 `#anchor`、路径里带 `%20`，都按 Obsidian 的方式解析——链接走元数据缓存解析，不是对字符串做手术。
- 选了 `短链`，宿主给出了短链就写短链；没给出来会提示原因，并改用直链。

## 和 RCGUI 之间怎么通信

| 路由 | 方向 | 说明 |
| --- | --- | --- |
| `GET /plugin/imagehost/ping` | 插件 → 宿主 | 只做探测：回复里的 `plugin` 必须是 `imagehost`，端口上换了别的服务会被拒。 |
| `POST /plugin/imagehost/upload?name=…` | 插件 → 宿主 | body 就是图片字节，不走 multipart——宿主对 multipart 的字段有体积上限。 |
| 上传响应 | 宿主 → 插件 | `url`、`short_url`、`compressed`、`deduped`、`short_error` 决定提示文案和用哪条链接。 |

两个超时都是量出来的：探测 2.5 秒，上传 10 分钟。本机服务往远程推的速度大约是 75 KB/s，20 MB 的截图要跑好几分钟——以前用两分钟上限，会把还在走的正常上传砍掉。

## 出问题先看这里

- **没找到 RCGUI 的 HTTP 服务** —— RCGUI 没开，或它的 HTTP 服务关了，或端口挪了。去 RCGUI 设置里打开服务，再按一次自动检测。
- **端口上跑的不是 imagehost 插件** —— 那个端口上有别的东西在应答。核对端口号，或看 RCGUI 自己怎么说。
- **上传超时：等了 600 秒服务端还没回** —— 图片很可能已经在往上走了，先去看 RCGUI 那个 imagehost 面板再粘一遍。同一个文件再粘一次会拿到已有链接，不会重复占空间。
- **HTTP 413** —— 文件超过宿主的体积上限（`体积上限`，默认 20 MB）。在 RCGUI 的 imagehost 面板里把上限调大，或者打开 `上传前真的缩小图片` 让它先重编码再传。
- **短链没成** —— 宿主那边短链模板没配好。这期间用直链，不影响插图。
- **图片已上传，但删除本地文件失败了** —— Obsidian 拒绝了回收站调用；链接是好的，附件手动删掉即可。

## 构建

```bash
npm install
npm run build      # esbuild 产出 main.js
npm run dev        # 改文件就重构建
```

除了 `manifest.json`，Obsidian 只加载 `main.js` 这一个产物；`src/` 是 TypeScript 源码，不随分发。重新构建后在 Obsidian 里重载插件。

## 已知限制

- 按「一个库一个主人」设计：设置按库存，上传也不归属到某个人。
- 链接只在宿主能服务它的时候有效——直链指向你的远程，代理形态则要 RCGUI 开着。
- `上传后删除本地文件` 只能把库里的文件送进回收站；库外的文件一律不碰。
- 动图 GIF 永远不会被重编码，所以按原大小上传，可能撞上宿主上限。
- 插件没有 `styles.css`：状态栏和提示都是 Obsidian 原生样式。
